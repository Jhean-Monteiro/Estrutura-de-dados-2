==================================================
DIA 4 — ARRAYS E STRINGS (foco em std::string)
==================================================

Arrays estáticos: já dominado nos exercícios do Dia 2 (declaração, percorrer com for
tradicional e range-based for).

Operações de std::string:
- Concatenação com +: std::string completo = nome + " " + sobrenome;
  (em C isso exigia strcat manual, cuidando de buffer e \0)
- Tamanho: s.length() ou s.size() -- equivalente ao .length do JS, mas é MÉTODO
  (com parênteses), não propriedade.
- Acesso por índice: s[0] -- e DIFERENTE de JS/TS, std::string é MUTÁVEL:
  s[0] = 'K'; realmente altera a string. Em JS, str[0] = 'x' falha silenciosamente.
- Substring: s.substr(inicio, quantidade) -- segundo argumento é QUANTIDADE de
  caracteres, não índice final (diferente do .slice(start,end) do JS).
  s.substr(11) sem segundo argumento vai até o fim.
- Comparação: == e < funcionam direto (sobrecarga de operador), sem precisar de
  strcmp como em C. < compara lexicograficamente.
- Busca: s.find("substring") retorna a posição, ou std::string::npos se não achar
  (equivalente ao -1 do .indexOf() do JS, mas como tipo size_t não aceita negativo,
  usa esse valor especial npos).
- Percorrer: for (char c : s) -- mesma lógica do range-based for de array, porque
  string se comporta como sequência de char.

Erro comum: instrução executável (como std::cout <<) fora de qualquer função, solta
no escopo global do arquivo, dá erro de compilação ("no storage class or type
specifier"). Só DECLARAÇÕES (variável, função, struct) podem ficar no nível global;
toda instrução que EXECUTA algo precisa estar dentro do corpo de uma função (main ou
outra).

Técnica de dois ponteiros/índices (fixada com exercício de palíndromo):
  bool isPalindrome(std::string s) {
      int inicio = 0;
      int fim = s.length() - 1;
      while (inicio < fim) {
          if (s[inicio] != s[fim]) return false;
          inicio++;
          fim--;
      }
      return true;
  }
- Um índice anda do início pro fim, outro do fim pro início, se encontram no meio.
- Evita comparar o mesmo par duas vezes (o que aconteceria percorrendo a string
  inteira com um for normal comparando com o espelho).
- Essa técnica reaparece depois em: inverter array, listas encadeadas, etc.

==================================================
DIA 5 — PONTEIROS (revisão vinda de C + comparação com referência)
==================================================

Base (igual C):
  int x = 10;
  int *p = &x;    // p guarda o ENDEREÇO de x
  std::cout << *p; // *p faz dereference: acessa o VALOR no endereço -> 10

Ponteiro vs Referência -- tabela de decisão:
                          Ponteiro (int *p)       Referência (int &r)
  Pode ser nulo?          Sim (nullptr)           Não, sempre vinculada a algo válido
  Pode "reapontar"?       Sim, p = &outraVar;     Não, fixa na variável original
  Precisa de * pra usar?  Sim                     Não, usa direto
  Precisa inicializar já? Não                     Sim, obrigatório
  Suporta aritmética?     Sim (p++, p+1)          Não existe esse conceito
  Uso típico              Nós de lista/árvore,     Parâmetros de função, evitar cópia
                          memória dinâmica

nullptr (C++ moderno) substitui o NULL de C (que era só um 0 disfarçado) -- tipo
próprio, mais seguro, evita ambiguidade em sobrecarga de função.

Ponteiro e array:
  int arr[5] = {10,20,30,40,50};
  int *p = arr;         // nome do array decai pro endereço do 1º elemento
  *(p+1) == 20;          // aritmética de ponteiro anda no tamanho do tipo
  p[2] == 30;             // p[i] é açúcar sintático pra *(p+i)

Regra prática de quando usar cada um: referência pra parâmetro de função (alterar
original / evitar cópia); ponteiro quando o vínculo PRECISA poder ser nulo ou mudar
de alvo ao longo do tempo -- exatamente o caso do campo "proximo" de um nó de lista
encadeada.

==================================================
DIA 6 (enxuto, sem OOP) — STRUCT
==================================================

Como o professor aceita estilo C, não é necessário usar class/OOP completo (private,
construtores, etc). struct resolve tudo que ED básica precisa.

  struct No {
      int valor;
      No *proximo;   // ponteiro pro mesmo tipo -- válido pq ponteiro tem tamanho fixo
  };

Diferença de C: depois de declarar "struct No {...}", pode usar só "No" direto sem
repetir a palavra struct toda vez (em C puro, sem typedef, seria preciso "struct No").

Ponteiro pra struct usa -> pra acessar campos (em vez de . usado em struct direto):
  No *n = new No;
  n->valor = 10;      // equivalente a (*n).valor = 10;

==================================================
DIA 7 — MEMÓRIA DINÂMICA (new / delete)
==================================================

Stack vs Heap:
- Stack: onde vivem variáveis normais (int x, arrays fixos). Alocada e liberada
  AUTOMATICAMENTE pelo compilador conforme a função entra/sai de escopo. Tamanho
  precisa ser conhecido em tempo de compilação.
- Heap: memória pedida manualmente EM TEMPO DE EXECUÇÃO. Continua existindo até
  liberação explícita, mesmo depois da função que criou ela ter terminado. Essencial
  pra estruturas que crescem dinamicamente (listas, árvores).

new / delete (equivalente C++ do malloc/free de C, mais simples):
  No *n = new No;      // aloca no heap, sem sizeof nem cast manual
  n->valor = 10;
  n->proximo = nullptr;
  delete n;             // libera a memória

Memory leak: se faz new e nunca faz o delete correspondente (ou perde a única
referência ao endereço, ex: n = nullptr; antes de dar delete), a memória fica presa
e inacessível até o programa fechar. Acontece com frequência ao remover nó de lista
sem deletar antes de perder a referência.

Use-after-free (erro cometido e corrigido na prática, no exercício de remover nó):
  delete temp;
  temp->proximo = ...;   // ERRADO: usa temp DEPOIS de já ter liberado a memória dele
- delete não "limpa" o ponteiro, só libera a memória -- usar o ponteiro depois é
  comportamento indefinido (pode parecer funcionar por sorte, ou crashar).
- Regra: sempre RELIGAR os ponteiros vizinhos ANTES de dar delete no nó removido.

DIA 9 — LISTA ENCADEADA (implementação completa do zero)
==================================================

Struct base:
  struct No {
      int valor;
      No *proximo;
  };

Percorrer a lista (usado em imprimirLista e buscar):
  No *temp = cabeca;
  while (temp != nullptr) {
      // usar temp->valor aqui
      temp = temp->proximo;
  }
- Checar "temp != nullptr" ANTES de acessar temp->valor evita crash em lista vazia.
- Erro comum evitado: usar while(true) com break dentro de um if verificando
  temp->proximo == nullptr causa DUPLICAÇÃO do penúltimo elemento -- o jeito correto
  é checar a condição de parada na ENTRADA do loop, não escondida num if no meio.

inserirInicio -- O(1), sempre imediato:
  No* inserirInicio(No *cabeca, int valor) {
      No *novo = new No;
      novo->valor = valor;
      novo->proximo = cabeca;  // novo aponta pro antigo primeiro
      return novo;              // novo nó é a nova cabeça
  }
- Função recebe a cabeça atual e RETORNA a nova cabeça -- necessário porque cabeca
  dentro da função é uma cópia (passagem por valor); a única forma de "avisar" o
  chamador sobre a mudança é devolvendo o novo valor como retorno. Uso:
  lista = inserirInicio(lista, valor);

inserirFim -- precisa percorrer até o último nó (aquele com proximo == nullptr):
  No* inserirFim(No *cabeca, int valor) {
      No *novo = new No;
      novo->valor = valor;
      novo->proximo = nullptr;
      if (cabeca == nullptr) return novo;  // caso especial: lista vazia
      No *temp = cabeca;
      while (temp->proximo != nullptr) {   // note: para ANTES do último, não depois
          temp = temp->proximo;
      }
      temp->proximo = novo;
      return cabeca;  // cabeça não muda, só cresce no fim
  }

remover -- o mais complexo, precisa de DOIS ponteiros simultâneos (anterior + atual)
pra religar a lista pulando o nó removido, já que lista encadeada não anda pra trás:
  No* remover(No *cabeca, int valor) {
      if (cabeca == nullptr) return cabeca;               // caso 1: lista vazia
      if (cabeca->valor == valor) {                        // caso 2: remover a cabeça
          No *novaCabeca = cabeca->proximo;
          delete cabeca;
          return novaCabeca;
      }
      No *anterior = cabeca;                                // caso 3: meio ou fim
      No *atual = cabeca->proximo;
      while (atual != nullptr) {
          if (atual->valor == valor) {
              anterior->proximo = atual->proximo;  // RELIGA primeiro
              delete atual;                          // só depois DELETA
              return cabeca;
          }
          anterior = atual;
          atual = atual->proximo;
      }
      return cabeca;  // caso 4: valor não encontrado, lista intacta
  }

buscar -- mais simples, só percorre e compara, sem religar nada:
  bool buscar(No *cabeca, int valor) {
      No *temp = cabeca;
      while (temp != nullptr) {
          if (temp->valor == valor) return true;
          temp = temp->proximo;
      }
      return false;
  }
